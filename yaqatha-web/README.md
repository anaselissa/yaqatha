# يَقَظَة — الواجهة العامة (Astro)

الصفحات العامة للموقع، مرتبطة بطبقة PostgreSQL/Supabase (`yaqatha-db`) عبر REST بالمفتاح العام فقط.
كل القراءات تمر عبر RLS؛ لا مفاتيح سرية في هذا المشروع.

## التشغيل المحلي (بلا Supabase حقيقي)

```bash
npm install
dev/up.sh            # PostgreSQL + بيانات تطوير + PostgREST + وكيل /rest/v1 + الموقع على :4321
npm test             # الموقع العام (10 مجموعات)
npm run test:e2e     # رحلة المستخدم في متصفح حقيقي (18 اختبارًا؛ RUNTIME=cloudflare لتشغيلها على workerd)
npm run test:admin   # عمليات الإدارة عبر REST/RPC بصلاحيات الفريق (6)
npm run test:a11y    # axe على 14 صفحة
npm run test:resilience   # سقوط القاعدة وتعافيها
npm run check        # أنواع TypeScript
```
`dev/` لتطوير المحلي فقط: `dev/db` نسخة من `yaqatha-db`، و`dev/dev-seed.sql` **بيانات تطوير** كل عناوينها «[تجريبي]» ولا تُطبَّق على الإنتاج أبدًا.
يتطلب `dev/stack.sh` PostgreSQL 16 محليًا وملف PostgREST الثنائي في `/home/claude/tools/postgrest` (عدّل المسار في السكربت).

## النشر

التفاصيل الكاملة والخطوات التي تخصك في **`docs/SUPABASE_SETUP.md`**. المحوّل الحالي يستهدف Cloudflare **Workers** (لا Pages).

## البنية

| المسار | الغرض |
|---|---|
| `src/lib/api.ts` | عميل REST خفيف، `DataError`، 416 → نتيجة فارغة |
| `src/lib/data.ts` | كل الاستعلامات (لا منطق أعمال: القاعدة هي المرجع) |
| `src/lib/page.ts` | `load()`: سقوط القاعدة ⇒ 503 + صفحة خطأ ودودة |
| `src/middleware.ts` | CSP وترويسات الأمان وCache-Control (`s-maxage=60`) |
| `src/pages/*` | الصفحات وفق خريطة الموقع، و`sitemap.xml` و`robots.txt` |
| `src/styles/global.css` | النظام البصري («الفجر»: #081824 / #b5934b / #e9d3a4) |
| `src/config.ts` | `FEATURES.accounts` (مفعّل الآن بعد اختبار تدفقاتها) |

## ما نُفّذ

الرئيسية، اكتشف احتياجك، الأبواب، الاحتياجات، المجالات، الموضوعات، المكتبة (تصفية + ترقيم)، المادة (Markdown آمن، مصدر، فيديو بالنقر)،
المسارات (آخر إصدار منشور، الخطوات، ملخص التغييرات)، صفحة الخطوة (noindex)، البحث العربي، عن يقظة/الخصوصية/الشروط، 404،
sitemap وrobots، تحويل 301 عند تغيير الروابط، JSON-LD (WebSite/Breadcrumb/Article/HowTo).

## وظائف المستخدم (نُفِّذت واختُبرت)

الدخول والخروج بـ Google (PKCE)، الجلسة والتجديد التلقائي، استعادة الوجهة والنية المعلقة (بدء مسار/حفظ مادة/هدف الزائر)،
رحلتي، المسارات والتقدم وحالات الخطوات، الانتقال بين الإصدارات (معاينة + تأكيد)، الأهداف (حالات/أرشفة/استعادة/ربط/حذف)،
المحفوظات، البلاغات، حذف الحساب. الصفحات العامة مخبَّأة وخالية من بيانات المستخدم؛ حالته تُجلب بـ`/api/state` (no-store).

## ما لم يُنفَّذ بعد

لوحة الإدارة (بنيتها وعملياتها المختبرة في `docs/ADMIN.md`)، وتجربة الدخول على Google/Supabase الحقيقيين (انظر `docs/SUPABASE_SETUP.md`).

## يحتاج مراجعة بشرية

- نصوص «الخصوصية» و«الشروط» و«عن يقظة» مسودات معقولة، لكنها قانونية الطابع وتحتاج مراجعتك قبل الإطلاق (وإضافة وسيلة تواصل).
- هل يعمل `s-maxage` على Cloudflare Pages كما هو متوقع؟ يلزم قياسه بعد النشر (قد تحتاج Cache Rule).
