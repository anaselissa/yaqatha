# يَقَظَة — الواجهة العامة (Astro)

الصفحات العامة للموقع، مرتبطة بطبقة PostgreSQL/Supabase (`yaqatha-db`) عبر REST بالمفتاح العام فقط.
كل القراءات تمر عبر RLS؛ لا مفاتيح سرية في هذا المشروع.

## التشغيل المحلي (بلا Supabase حقيقي)

```bash
npm install
dev/up.sh            # PostgreSQL + بيانات تطوير + PostgREST + وكيل /rest/v1 + الموقع على :4321
npm test             # الموقع العام (10 مجموعات)
npm run test:e2e     # رحلة المستخدم في متصفح حقيقي (18 اختبارًا؛ RUNTIME=cloudflare لتشغيلها على workerd)
npm run test:admin   # عمليات الإدارة عبر REST/RPC بصلاحيات الفريق (6)
npm run test:a11y    # axe على 14 صفحة
npm run test:resilience   # سقوط القاعدة وتعافيها
npm run check        # أنواع TypeScript
```
`dev/` للتطوير المحلي فقط (يطبّق هجرات `../yaqatha-db` مباشرة)، و`dev/dev-seed.sql` **بيانات تطوير** كل عناوينها «[تجريبي]» ولا تُطبَّق على الإنتاج أبدًا.
يتطلب `dev/stack.sh` PostgreSQL 16 محليًا وملف PostgREST الثنائي في `/home/claude/tools/postgrest` (عدّل المسار في السكربت).

## النشر

التفاصيل الكاملة والخطوات التي تخصك في **`docs/SUPABASE_SETUP.md`**. المحوّل الحالي يستهدف Cloudflare **Workers** (لا Pages).

## البنية

| المسار | الغرض |
|---|---|
| `src/lib/api.ts` | عميل REST خفيف، `DataError`، 416 → نتيجة فارغة |
| `src/lib/data.ts` | كل الاستعلامات (لا منطق أعمال: القاعدة هي المرجع) |
| `src/lib/page.ts` | `load()`: سقوط القاعدة ⇒ 503 + صفحة خطأ ودودة |
| `src/middleware.ts` | CSP وترويسات الأمان وCache-Control (`s-maxage=60`) |
| `src/pages/*` | الصفحات وفق خريطة الموقع، و`sitemap.xml` و`robots.txt` |
| `src/styles/global.css` | النظام البصري («الفجر»: #081824 / #b5934b / #e9d3a4) |
| `src/config.ts` | `FEATURES.accounts` (مفعّل الآن بعد اختبار تدفقاتها) |

## ما نُفّذ

الرئيسية، اكتشف احتياجك، الأبواب، الاحتياجات، المجالات، الموضوعات، المكتبة (تصفية + ترقيم)، المادة (Markdown آمن، مصدر، فيديو بالنقر)،
المسارات (آخر إصدار منشور، الخطوات، ملخص التغييرات)، صفحة الخطوة (noindex)، البحث العربي، عن يقظة/الخصوصية/الشروط، 404،
sitemap وrobots، تحويل 301 عند تغيير الروابط، JSON-LD (WebSite/Breadcrumb/Article/HowTo).

## وظائف المستخدم (نُفِّذت واختُبرت)

الدخول والخروج بـ Google (PKCE)، الجلسة والتجديد التلقائي، استعادة الوجهة والنية المعلقة (بدء مسار/حفظ مادة/هدف الزائر)،
رحلتي، المسارات والتقدم وحالات الخطوات، الانتقال بين الإصدارات (معاينة + تأكيد)، الأهداف (حالات/أرشفة/استعادة/ربط/حذف)،
المحفوظات، البلاغات، حذف الحساب. الصفحات العامة مخبَّأة وخالية من بيانات المستخدم؛ حالته تُجلب بـ`/api/state` (no-store).

## لوحة الإدارة (`/admin`)

**المرحلة 1 (منفَّذة ومختبرة):** حماية `/admin` (يتطلب الدخول، وغير الموظف يرى 404)، الرئيسية بأرقام المحتوى،
المواد (قائمة بتصفية وبحث، إضافة من رابط يوتيوب مع جلب العنوان والقناة تلقائيًا، تعديل، نشر/إخفاء بنقرة، حالة المراجعة،
منع الكتابة فوق تعديل زميل)، ونشر الاحتياجات والمجالات مع عدد موادها المنشورة، والفريق (المدير يضيف مديرًا أو محررًا ببريده، ويغيّر الدور، ويزيل). لا تعديل على قاعدة البيانات في هذه المرحلة.
`npm run test:admin-ui` (10 اختبارات في متصفح بمقاس الهاتف؛ يتطلب `dev/up.sh`).

**المرحلة 2أ (منفَّذة ومختبرة): محرر المسارات.** إنشاء مسار وإصداره الأول، الخطوات (إضافة، تعديل، ربط بمادة، ترتيب، حذف)،
النشر، تصحيح نص الإصدار المنشور، إصدار جديد بملخص تغييرات إلزامي، إيقاف البدء الجديد، سحب الإصدار. بلا تعديل على القاعدة.
`npm run test:admin-paths` (6 اختبارات متصفح).

**المرحلة 2ب (منفَّذة ومختبرة؛ تتطلب الهجرة 8): السلاسل وختام المسار.** سلسلة = حلقات مرتبة؛ إنشاؤها من روابط يوتيوب دفعة واحدة
(حتى 25، مع جلب العناوين، وإعادة استخدام المقطع الموجود)، ترتيب الحلقات ونشرها، صفحة عامة `/series/<slug>` و«الحلقة التالية» في صفحة كل حلقة،
وتحويل السلسلة إلى مسار بنقرة. ختام المسار: أهداف مقترحة يتبنّاها المستخدم بنقرة، ومسارات تالية. الصفحات العامة تعمل حتى قبل تطبيق الهجرة.
`npm run test:admin-series` (6 اختبارات متصفح).

**المرحلة 3 (منفَّذة ومختبرة؛ تتطلب الهجرة 9): الأثر والمتابعة المباشرة.** أرقام الأثر في رئيسية اللوحة (مستخدمون، نشِطون،
بدء وإكمال لكل مسار، أهداف مقترحة متبنّاة) عبر `admin_stats()` بأعداد مجمّعة فقط. صفحة `/support`: زر واتساب الفريق برسالة جاهزة،
ونموذج طلب متابعة (بعد الدخول؛ طلب مفتوح واحد؛ سحب وحذف فوري). اللوحة: «طلبات المتابعة» (المدير يرى الكل ويسند،
والمتابِع يرى ما أُسند إليه فقط)، و«الإعدادات» (رقم واتساب، إيقاف الاستقبال، قسم الأخوات، مدة الرد، المتابِعون).
أرقام الهواتف لا تُسجَّل في سجل التغييرات. `npm run test:admin-followup` (8 اختبارات متصفح).

**المرحلة 4 (منفَّذة ومختبرة؛ تتطلب الهجرتين 10 و11):**
- «اختبر فهمك»: أسئلة اختيار من متعدد بعد المادة يضيفها الفريق من صفحة المادة في اللوحة؛ الزائر يرى النتيجة والشرح،
  والمسجّل تُحفظ إجابته الأولى (الصحة تحسبها القاعدة). `npm run test:quiz` (4).
- النقاط وسلسلة الأيام في «رحلتي» (`my_progress()`): خطوة 10، إجابة صحيحة 5، مسار مكتمل 30؛ لصاحبها فقط ولا ترتيب بين الناس.
- «من أين أبدأ؟» (`/start`): تعريف قصير وأسئلة اختيار يعدّلها الفريق من «ابدأ من هنا» في اللوحة، تقترح الاحتياج الأرجح
  مع مساره وموادّه، والإجابات لا تُحفظ. زر الرئيسية الأول يقود إليها. `npm run test:onboarding` (5).

**المرحلة 5أ (منفَّذة ومختبرة؛ بلا هجرة):** تثبيت الموقع على الهاتف (PWA): `public/manifest.webmanifest`، أيقونات
بفكرة اللوجو (شمس فوق الكثبان وطريق)، و`public/sw.js` (صفحة «بلا اتصال» `/offline/` وتخزين ملفات `/_astro/` الثابتة فقط؛
لا يُخزَّن أي محتوى شخصي). زر «ثبّت الآن» على أندرويد وتعليمات iPhone، وتذكير يومي في تقويم الهاتف (Google أو ملف
`/reminder.ics?t=HH:MM` بوقت الجهاز المحلي) في «رحلتي» و«الإعدادات». `npm run test:app` (4).

**المرحلة 5ب (بلا هجرة):** `/admin/reports` لبلاغات الزوار (المدير والمحرر؛ لا تظهر هوية المبلِّغ) — `npm run test:reports` (4).
ونقطة دخول Cloudflare مخصصة `src/worker.ts` (معالج Astro نفسه + `scheduled`) مع `wrangler.jsonc` (cron يومي) لإبقاء Supabase
المجاني نشطًا. تجربتها محليًا: `npx wrangler dev -c dist/server/wrangler.json` ثم
`curl -X POST 'localhost:8787/cdn-cgi/local/explorer/api/local/scheduled?worker=yaqatha-web' -d '{"cron":"17 5 * * *"}'`.

## يحتاج مراجعة بشرية

- نصوص «الخصوصية» و«الشروط» و«عن يقظة» مسودات معقولة، لكنها قانونية الطابع وتحتاج مراجعتك قبل الإطلاق (وإضافة وسيلة تواصل).
- هل يعمل `s-maxage` على Cloudflare Pages كما هو متوقع؟ يلزم قياسه بعد النشر (قد تحتاج Cache Rule).
